Gestión de inventario · .NET 8 + React

El stock no se edita.
Se registra.

En la mayoría de los sistemas de inventario alguien puede abrir un producto y escribir «120» donde decía «143». StockHex no tiene ese campo. La única forma de mover una existencia es asentar un movimiento, y el movimiento y el nuevo stock se guardan juntos: historial y saldo no pueden desincronizarse.

El caso de uso

Cuando la planilla deja de alcanzar

Una bodega pequeña vive con una hoja de cálculo hasta el día en que el número de la pantalla y el número del estante dejan de coincidir. Entonces empiezan las preguntas que la planilla no puede responder.

«Aquí dice 143 y en el estante hay 66.»

¿Cuándo se separaron? Sin un registro de cada variación no hay forma de reconstruirlo: sólo queda contar de nuevo y volver a escribir el número.

«¿Quién cambió esto?»

En una celda editable no queda rastro. Cada movimiento de StockHex se atribuye al usuario que lo registró, tomado de su sesión y no de un campo del formulario.

«Me equivoqué, lo borro.»

Borrar un error también borra la evidencia de que ocurrió. Aquí un movimiento equivocado no se edita ni se elimina: se corrige asentando su inverso.

«Que el bodeguero no toque los precios.»

Los roles no vienen fijos en el código. Se crean desde la interfaz y se les marca exactamente lo que pueden hacer, permiso por permiso.

Cómo funciona

Tres tipos de asiento, y una regla que los sostiene

Toda variación de existencias entra por el mismo sitio. El tipo decide qué le hace al saldo, y nada más puede tocarlo.

Entrada

Mercadería que llega: una compra, una devolución de cliente. Deja constancia del proveedor.

stock += cantidad

Salida

Mercadería que sale. Si el stock no alcanza, la operación se rechaza: nunca queda negativo.

stock −= cantidad

Ajuste

Un conteo físico. La cantidad no es una variación sino el saldo real que se quiere dejar asentado.

stock = cantidad

La regla

Un movimiento equivocado no se edita ni se borra: se registra su inverso. La reversión invierte la variación neta del original, así que es exacta para los tres tipos y sigue siendo correcta aunque después hayan pasado otros movimientos. El error y su corrección conviven en el historial, como en cualquier libro contable.

Las pantallas

Cómo se ve

Interfaz densa, pensada para operar con teclado y para leer muchas filas de un vistazo. Tema claro y oscuro, y todo filtro vive en la URL: refrescar conserva la consulta y el enlace se puede compartir.

Qué ofrece

Lo que ya viene resuelto

No es una maqueta: es un sistema con autenticación, permisos, concurrencia y despliegue, verificado contra una base de datos real.

Auditoría

Historial inmutable

El movimiento y el nuevo stock se guardan en un solo SaveChanges, así que no existe el estado intermedio en que uno se grabó y el otro no.

Autorización

Roles que se configuran

31 permisos en 9 módulos. El token lleva sólo el id del rol, nunca la lista de permisos: quitarle uno a alguien surte efecto en segundos, sin cerrarle la sesión.

Concurrencia

Dos bodegueros a la vez

Un token de concurrencia impide que dos movimientos simultáneos se pisen el saldo, y el reintento hace que esa protección no se traduzca en rechazos.

Sesiones

JWT con rotación

El refresco rota en cada canje. Si reaparece uno ya usado se asume robo y se corta la sesión completa. En la base sólo vive el hash.

Reportes

Agregados en la base

Valorización, stock bajo ordenado por déficit y actividad por período. Los totales los calcula SQL, no el navegador.

Despliegue

Un solo comando

Base de datos, API y frontend en Docker Compose. nginx sirve la interfaz y hace de proxy de la API: un único origen y nada de CORS que configurar.

Bajo el capó

Arquitectura limpia, y pruebas que la sostienen

Cuatro capas con el dominio en el centro y sin una sola referencia a Entity Framework ni a ASP.NET fuera de la infraestructura.

Levantarlo

Tres servicios, un comando

El compose levanta SQL Server, la API y el frontend, aplica las migraciones y crea el administrador inicial. Después, la aplicación está en localhost:8080.

El .env es obligatorio: sin clave de firma ni contraseña de administrador, no arranca. 

# clonar y configurar
$ git clone https://github.com/waka-code/StockHex.git
$ cd StockHex
$ cp .env.example .env

# y arriba
$ docker compose up -d --build

✔ sqlserver   healthy

✔ web         healthy
